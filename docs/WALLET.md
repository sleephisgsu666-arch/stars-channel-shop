# Оплата через баланс магазина

С 14.09.2026 новые покупки выполняются с внутреннего баланса. Это предоплата внутри магазина: 1 Telegram Star при пополнении даёт 1 единицу баланса. Баланс не является личным кошельком Telegram Stars, не переводится другим пользователям и не поддерживает произвольный вывод.

## Пользователь

1. `/start` → **«Баланс · Пополнить»**.
2. Выбрать сумму или «Другая сумма» и ввести целое число от 1 до 100000.
3. Прочитать условия, подтвердить пополнение, оплатить Stars invoice.
4. После successful_payment баланс увеличивается. Право входа в канал ещё не возникает.
5. Открыть каталог, выбрать разовый срок либо «Навсегда».
6. Подтвердить **«Купить с баланса»**. Если средств достаточно, одна транзакция списывает баланс и выдаёт право доступа.
7. Получить персональную ссылку и подать заявку на вход.

Повторная покупка продлевает оставшийся срок. Автопродления и самостоятельных списаний по расписанию нет. Бесплатные тарифы остаются доступны без списания.

## Администратор

- **Тарифы**: бесплатный, доступ на срок, навсегда. Recurring больше нельзя создать через форму или `/save`.
- **Пополнения / возвраты**: платежи Telegram Stars. Возврат пополнения отправляет Stars обратно через Telegram API.
- **Покупки с баланса**: оплаченные и ожидающие покупки. «Вернуть покупку на баланс» возвращает её стоимость внутрь магазина и отзывает её вклад в доступ.
- Для возврата потраченного пополнения сначала верните связанные покупки на внутренний баланс. Если пополнение финансировало несколько покупок, верните каждую из них. Активная история покупок находится в разделе покупок; полная связь хранится в wallet_allocations.
- При запросе возврата нетронутого пополнения сумма резервируется: её нельзя одновременно потратить. Worker повторяет Telegram refund до подтверждения. Если Telegram недоступен, резерв сохраняется.
- Статистика разделяет Stars, полученные от Telegram, покупки с баланса и оставшиеся средства пользователей. Пополнение не считается продажей конкретного продукта.

## Учёт и безопасность

`users.balance_stars` — целочисленный доступный остаток с CHECK >= 0. `wallet_entries` — журнал всех зачислений, списаний, возвратов и резервов. `wallet_allocations` связывает покупку с конкретными платежами пополнения. Runtime не может обновлять или удалять записи этих журналов.

Orders имеют `funding_source`: `topup`, `wallet`, `legacy`. Topup order не содержит product_id/plan_id. Покупка с баланса хранит snapshot цены и срока и не может быть оплачена через successful_payment. Grants дополнены уникальным purchase_order_id.

Зачисления сериализуются по пользователю; списания также блокируют соответствующий entitlement. Отрицательный остаток, двойной расход и двойная выдача при повторной доставке исключаются транзакцией, locks и UNIQUE. Стоимость и срок берутся из серверного order, а не из кнопки. Повторное нажатие подтверждения одного заказа не списывает средства снова. Для намеренного продления создаётся новый заказ выбором тарифа.

Повторный charge ID не зачисляется второй раз. Если Telegram подтвердил два разных реальных списания по одному пополнению, учитываются оба фактически полученных платежа. Возврат, пришедший раньше successful_payment, сохраняется в reversal inbox и не даёт последующему событию зачислить возвращённые деньги.

При внешнем возврате/chargeback уже потраченного пополнения система по allocations находит затронутые покупки. Они полностью отменяются; их стоимость возвращается на внутренний баланс, затем вычитается возвращённое пополнение. Средства из других пополнений сохраняются. Их независимые покупки и бесплатные/ручные grants не затрагиваются. Если покупка финансировалась несколькими пополнениями, она отменяется целиком, а части из невозвращённых пополнений снова доступны на балансе.

## Обновление существующего проекта

Остановите старые app/worker перед применением миграции. Для `Start.command` достаточно Ctrl+C и нового запуска — миграции применяются автоматически. Для Docker: backup → остановить app/worker → `docker compose run --rm migrate` → запустить обновлённые app/worker.

Миграция `7a171d0f4508` добавляет баланс (начальное значение 0), журналы и новые поля. Старые оплаты не превращаются в баланс: за них уже выдан доступ. История и существующие права сохраняются. Старые recurring планы становятся разовыми 30-дневными тарифами; snapshots старых orders остаются неизменными.

Worker раз в минуту пытается отменить автопродление ранее созданных нативных подписок. Доступ сохраняется до конца уже оплаченного периода. Нужен работающий worker и доступ к Telegram API; при ошибке отмена повторяется. Уже состоявшиеся старые списания обрабатываются как реальные платежи, а не теряются. Не удаляйте обработчики legacy payments до завершения миграционного периода и финансовой сверки.

Технический контракт пополнения: [официальные Telegram Stars payments](https://core.telegram.org/bots/payments-stars), currency=XTR, пустой provider_token, подтверждение по successful_payment. Реальные условия вашего магазина должны отдельно объяснять внутренний баланс и порядок возвратов; задайте TERMS_TEXT и TERMS_URL.
